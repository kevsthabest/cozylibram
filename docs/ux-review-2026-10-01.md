# UX/UI Review — Cozy Libram (`kevsthabest/cozylibram`)

**Date:** 2026-10-01
**Reviewer role:** senior UX/UI specialist (subagent review)
**Scope:** mobile-first PWA for a dark-romance reader's personal library. App v222, production screenshots (signed-in) + static code review.
**Method:** close study of 8 production screenshots (`docs/screenshots/`: library, book-modal, discover, stats — mobile + desktop), plus read-only code review of renderers (`js/095-gate.js`, `096-onboarding.js`, `100-nav.js`, `110/120-library.js`, `130-add.js`, `132/133-import.js`, `150-modal-discovery.js`, `155-authors.js`, `160-roulette.js`, `170-stats.js`, `180-settings.js`, `190-wishlist.js`, `195-coven.js`, `198-discovery.js`) and `styles.css`. No code was changed. The live app requires sign-in, so no interactive browsing was possible — every finding below cites a screenshot or a file:line.

## 1. Overall impression

Cozy Libram is a genuinely well-crafted app with a strong, cohesive identity — the dark BookTok-spice aesthetic (Playfair Display headlines, pink-on-near-black, line-art icons, ❦ ornaments) is applied consistently, and several flows show real product thinking: the book modal's contextual primary action ("Start Reading" → "Log Pages" → "Rate & Review") is the best kind of UX, onboarding step 1 deep-links straight into scan/search/import with zero wasted taps, and the import hub reports corrupted records by title instead of failing silently. Accessibility basics are in place (`:focus-visible` global, `prefers-reduced-motion` catch-all, `aria-label`s on icon buttons).

The weak spots cluster in three areas: **(a) small touch targets** — chips, small buttons, and the heart-rating row sit under the 44px mobile target; **(b) silent data loss** — modal edits are draft-until-Save with no dirty-check, so a swipe-dismiss after rating loses the rating; and **(c) the two heaviest flows for a several-hundred-book library (bulk import, LAN camera scanning) both have friction exactly where a phone-first user meets them** — the import hub is buried two levels deep in Settings with no progress on large files, and live camera scanning needs HTTPS, which the home-LAN setup doesn't provide. Nothing here needs a redesign; it's a punch list, ordered below.

## 2. Strengths

- **Contextual primary action in the book modal** (`js/150-modal-discovery.js:1123-1130`): the big pink button reads the shelf — "Start Reading" (TBR), "Log Pages" (reading), "Rate & Review" (read), "Give it another go" (DNF). One glance tells the user the single most likely next step. This is excellent.
- **Onboarding that respects the user's time** (`js/096-onboarding.js`): 3 steps, skippable every step, and step 1's buttons ("Search for a Book", "Scan an ISBN", "Import a Library") exit the tour *directly into the real flow* — no dead-end tutorial screens.
- **Honest import UX** (`js/132-import.js`, `js/133-bookmory.js`): pre-import preview shows "Detected: Goodreads — 214 books (12 already on your shelves, will be skipped)"; corrupted Bookmory records are reported **by title** ("worth adding by hand") instead of failing silently. Result toasts give exact counts.
- **Progress tracking done right** (`js/150-modal-discovery.js:925-955`): manual page input + −10/−1/+1/+10 steppers, Enter-to-set, sessions auto-logged with a readable recent-sessions list. The "Update Progress" pill on the library home card is one tap from the thing she does daily.
- **Empty states with a way forward** (`js/050-helpers.js:144-155` shared helper): every major empty state pairs plain copy with a CTA ("Your TBR is empty / Add some books first, then come back and spin." → Add books).
- **Dismissal redundancy on overlays**: swipe-down-to-close, Android system-back (v220), Escape key, and an explicit back arrow — a phone user can never get stuck in the modal.
- **Aesthetic cohesion**: one accent pink, one gold, serif display type, consistent card language (14px radius, 1px `--line` borders), theme-following social tab name, per-theme ❦ flourishes. It looks like one app, not 40 features.

## 3. Issues & improvement opportunities

| ID | Severity | Screen(s) | Problem | Recommendation |
|----|----------|-----------|---------|----------------|
| UX-01 | Medium | Book modal (desktop) | The book description renders **twice**: once beside the cover (`descHTML('m-desc-hero', 'd-hero-desc')`, `js/150-modal-discovery.js:1017`, shown on desktop via `styles.css:1975-1978`) and again under "ABOUT THIS BOOK" on the Details tab. On a long modal this is pure bloat — the user reads the same blurb twice within one scroll. | Drop one. Keep the Details-tab copy (it sits with tropes/notes context) and remove the hero instance, or keep the hero blurb and cut "ABOUT THIS BOOK" to a "Read more" expansion only. |
| UX-02 | Polish | Book modal (mobile + desktop) | "YOUR RATING" shows 5 tappable hearts **plus** a "Tap to rate" pill (`js/150-modal-discovery.js:883,1031`). The pill is redundant — tapping a heart *is* rating — and it competes visually with the live word label ("Loved it", "Meh") that already appears beside the hearts. Two labels for one control. | Remove the pill; keep the hearts + the dynamic word label. If a hint is needed, use `aria-label` / a one-time coach mark, not a permanent second control. |
| UX-03 | Polish | Stats (mobile + desktop) | Empty values are inconsistent: "0 BOOKS FINISHED", "0 PAGES" but "— AVG RATING", "— READING TIME" (`js/170-stats.js:630-631, 962-963`). Scanning the row, it reads like a bug rather than a convention. | Pick one language for "no data yet": either `—` everywhere, or keep `0` for counts and add a faint caption ("finish a book to see averages"). | UX-04 | Polish | Library home | The greeting bucket is 5–12 morning / 12–17 afternoon / **everything else "evening"** (`js/120-favorites.js:308-310`) — so at 1:49 AM (when the screenshots were taken) it says "Good evening, beautiful". A reader up at 2 AM gets called out by the wrong time of day. | Add a night bucket: 22–5 → "night" ("Good night, beautiful" / "Burning the midnight oil, beautiful"?). Keep it on-brand, but correct. |

Shouty metadata undermines the otherwise polished typography. | Normalize display casing for author names at render (title-case unless the string is already mixed-case), or fix at import/enrichment time. The inline expansion is good; the label undersells it. |
| UX-08 | Low | Bottom nav (all screens) | The social tab renames itself with the theme — "Coven", "Night Court", "Book Club", "Grove"… (`js/195-coven.js:14-28`). | UX-10 | Low | Book modal | Share and Remove live behind the ⋮ "More actions" menu (`js/150-modal-discovery.js:986-993`). ## 4. Prioritized top-5 (best effort-to-impact for a phone-first reader)

1. **UX-15 — 44px touch targets (CSS-only).** One rule (`min-height: 44px` on `.btn.sm`, `.btn.small`, `.chip`, rating picker buttons, widened via padding) fixes every undersized control in the app — Coven accept/decline, scan "Add to TBR", all filter chips, the heart-rating row. Smallest effort, broadest impact.
2. **UX-11 — Stop silently discarding modal edits.** A dirty-check confirm on dismiss, or committing rating/axis taps live like the status button already does. Prevents the worst kind of UX bug: the user did the work and the app threw it away.
3. **UX-13 — Surface the import hub on the Add screen.** An "Import a library" row next to Scan/Search turns a 5-tap buried flow into a front-door flow — for a several-hundred-book library this is *the* onboarding moment.
4. **UX-23 — Author-detail back-gesture history entry.** Small fix using the existing v220 overlay-history pattern; resolves the known "back goes Home" bug Kevin reported.
5. **UX-17 — LAN HTTPS for camera scanning.** `server.py` + mkcert self-signed cert so live barcode scanning works on the home LAN — un-degrading the headline phone feature where it's used most. (Deployment change, not app code.)

## 5. Could not evaluate

- **Gesture feel**: swipe-down-to-close (v215) and the v220 back-gesture are in code, but reliability/feel can't be judged statically — needs a phone in hand.
- **Coven/social flows beyond code**: no screenshots of invite, friend shelves, or shared preview modal; assessment is from `js/195-coven.js` markup only.
- **Import performance at scale**: no per-book progress on CSV/Bookmory paths was observed in code (flagged as UX-14), but actual timing on a 500-book file wasn't measured.
- **Detailed stats explorer, reading-log calendar, theme picker, cover picker, trope tabs**: no screenshots; code reviewed only where cited.
- **Real-device rendering**: tap-target sizes are padding arithmetic (no explicit `min-height` in CSS to measure against); actual pixels, font rendering, and the 11px `--faint` labels need on-device confirmation.
- **Server-side gate behavior** when cloud isn't configured (only client-visible status lines reviewed).
- Whether the stale "works fine without sign-in" Settings copy (UX-12) has actually confused anyone — code contradiction only, no user report.
