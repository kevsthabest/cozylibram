# Security Review — Cozy Libram (`kevsthabest/cozylibram`)

**Date:** 2026-10-01
**Scope:** Read-only review of `~/workspace/booktok` (app v222). Vanilla HTML/CSS/JS PWA, Cloudflare Pages (`https://cozylibram.pages.dev`), Supabase backend (project "Spicy", `dvhimjkrroxuatthiizc`, us-west-2), home-PC `server.py` dev server.
**Method:** Static code review of all client JS, `server.py`, Pages Functions, Supabase SQL, service worker, live header check. No secrets are reproduced in this report.

## Executive summary

The app's security posture is genuinely above average for a personal project: secrets stay server-side by design (`/config.js` carries only capability flags), Supabase RLS is thorough and well-reasoned (per-user book isolation, circle-scoped friend reads, creator-attributed metadata writes), `esc()` is applied systematically across nearly every XSS sink, SSRF guards cover the proxy endpoints, and the analytics pipeline enforces its enum-only allowlist in code. That said, the sweep found **two stored-XSS holes in the Year-in-Books renderer** (unescaped book title and author name at `js/170-stats.js:617,619` — a 21-character `<svg onload=…>` payload fits the 22-char truncation), and **one critical server finding**: `server.py` serves its own directory with no filtering, so `GET /server-config.json` — and the entire `/.git/` history — is downloadable by anyone who can reach the port, which binds `0.0.0.0` with no LAN gating since v53. Separately, the Cloudflare Pages `/api/*` proxies (LLM inference, Hardcover) are intentionally public and unauthenticated, so anyone on the internet can burn the owner's API quota; per-IP rate limits blunt casual abuse but the code itself admits they don't stop a distributed attacker. The remaining findings are medium/low hardening items. No secrets were found committed in the working tree or recent git history.

### XSS / client-side sweep — complete (dedicated adversarial pass + spot checks)

A dedicated read-only sweep checked every `innerHTML`/`outerHTML`/`insertAdjacentHTML` sink in the remaining 16 client files (`130-add`, `180-settings`, `198-discovery`, `199-admin`, `110-library`, `155-authors`, `160-roulette`, `170-stats`, `190-wishlist`, `196-recos`, `197-social-stats`, `140-collections`, `137-shelf`, `138-editions`, `105-account`, `136-coverpicker`), plus `eval`/`postMessage`/open-redirect/dangerous-primitive checks, the analytics allowlist, and storefront links. **Two stored-XSS holes found** (SEC-12, SEC-13 — Year-in-Books, both one-line `esc()` fixes); everything else holds.

Spot checks by the primary reviewer (also verified): `esc()` (`js/050-helpers.js:4-8`) correctly escapes `&<>"'`; quotes (`js/150-modal-discovery.js:1497-1499`), descriptions (`:403-406`, tags stripped then escaped), tropes/categories (`:410-417`), import previews (`js/132-import.js:249-250`, `js/133-bookmory.js:415`), friend names/avatars (`js/195-coven.js:270,314,411,444`; avatar ids allowlisted at `:204-205`), and error messages (`js/133-bookmory.js:431`) are all escaped. Quote page numbers are numeric-coerced at save (`js/150-modal-discovery.js:1519`). No `postMessage` handlers, no `message` listeners, no `eval`/`new Function`/string `setTimeout`/`setInterval`, no `javascript:` URLs, no `srcdoc`, no iframes, no `location.href=`/`location.assign`/`window.open` writes anywhere in `js/`. The only `location.hash` use is a strict equality check (`095-gate.js:200`) — no hash content flows into HTML. Storefront links use hardcoded retailer domains + `encodeURIComponent`, rendered with `target="_blank" rel="noopener"` and escaped URLs (`js/150-modal-discovery.js:1052-1053`); ISBN stripped to `[0-9X]`; region override validated against `STORE_REGIONS`. The analytics `track()` allowlist is enforced in code — unknown event names dropped, props restricted to declared enums (`js/065-analytics.js:139-165`), `PROP_VALUES` contains only source/shelf/axis enums (`:79-88`) except the `kind` gap (SEC-15); `search_performed` carries no props, so query text is never logged. All ~40 `track()` call sites audited — no titles, authors, ISBNs, ratings, notes, or emails. Non-security notes: `track('reco_viewed', …)` at `198-discovery.js:833` is silently dropped (event not in `EVENT_DEFS` — dead instrumentation); `source` values outside the enum (`'preview'`, `'author-missing'`, `'coven-reco'`) are silently dropped by validation (data loss, not leakage).

**Files audited clean (all interpolations escaped or internally generated):** `130-add.js` (search results, ISBN/barcode lookup, bulk-import rows; `toast()` uses `textContent`); `180-settings.js` (theme/accent/region options from internal constant tables; the one unescaped `partitionLabel` is inside `confirm()` — plain text, not HTML); `198-discovery.js` (release tiles, streamed progress strings, reco cards); `199-admin.js` (Observatory tables, log viewer — the unescaped `e.level` at `:257` is safe: `AppLog._write` coerces levels, `002-log.js:19`); `110-library.js`, `155-authors.js`, `190-wishlist.js` (cards/tiles/rows, including `data-id`/`title` attributes); `160-roulette.js` (slot title uses `textContent`); `196-recos.js` (friend names/titles); `197-social-stats.js` (`style="width:…"` safe — score is `Math.round`'d at `:103`; avatars allowlisted); `137-shelf.js` (`shelfSpineLabel()` self-escapes); `138-editions.js` (errors via `textContent`); `105-account.js` (email/profile escaped; photo URLs are client-minted `data:` URLs); `136-coverpicker.js`; `140-collections.js` (series/authors/titles/covers escaped — only the `b.id` attributes flagged in SEC-14).

## Prioritized remediation plan

0. **[HIGH — ship first, trivial] Fix the two Year-in-Books stored-XSS holes.** Wrap `d.longest.title.slice(0, 22)` and `d.topAuthor[0].slice(0, 22)` in `esc()` at `js/170-stats.js:617,619`. Two one-line changes; while at it, normalize the unescaped `b.id` interpolations (SEC-14) to `esc(b.id)`. Effort: S. No owner decision needed — this is a straight bug fix.

1. **[CRITICAL] Block sensitive paths in `server.py`.** In `Handler.do_GET`, return 404 for `/server-config.json`, `/.git/`, and any dotfile/dot-directory *before* falling through to `super().do_GET()`. Effort: S (10 lines). Additionally, re-add the LAN gating removed in v53 — or at minimum bind `127.0.0.1` when a `--public` flag isn't passed — so a firewall/UPnP surprise can't expose the port. **Owner decision:** he explicitly asked for the gating to be removed in v53; re-adding any form of it needs his go-ahead, but the `server-config.json` blocklist does not and should ship regardless.
2. **[HIGH] Rotate the Hardcover token.** It's the highest-blast-radius secret given the open `/api/hardcover` proxy, and the chat-pasted token is believed unrevoked. Rotate in Hardcover dashboard → update `server-config.json` (home PC) and Pages env `HARDCOVER_TOKEN`. **Owner action required.**
3. **[HIGH] Put the Pages `/api/*` proxies behind real abuse controls.** Cheapest effective: add a Cloudflare dashboard rate-limiting rule on `/api/*` (the code already recommends this in `functions/_lib/rate-limit.js`). Stronger: require a per-install secret — e.g. the client sends a `X-Libram-Key` derived from a Pages env var the owner pastes once per device in Settings; the Functions reject without it. Effort: M. **Owner decision:** whether to accept a one-time per-device setup step.
4. **[HIGH] Constrain `/api/hardcover` to an allowlisted query set.** The app only needs a handful of query shapes (book search, series lookup, edition detail). Hash/allowlist the known shapes server-side and reject the rest, or move query construction server-side with client-supplied parameters. Effort: M.
5. **[MEDIUM] Add the missing headers to `_headers`.** `X-Frame-Options: DENY` (or `frame-ancestors 'none'`), `Strict-Transport-Security: max-age=31536000; includeSubDomains` (verify no HTTP-only subdomains first), `X-Content-Type-Options: nosniff` (already present via Cloudflare, but pin it). CSP: start with `default-src 'self'` + narrow allowances and iterate — the inline scripts make this the long pole. Effort: S for the first three, L for CSP.
6. **[MEDIUM] Decide the signup posture.** Either keep open signup (and accept that "private" = URL obscurity — then remove the `circle_invites` world-readable policy or shorten code lifetimes), or gate it: disable public signup in Supabase Auth and invite the known users. Effort: S (a dashboard toggle + RLS tweak). **Owner decision.**
7. **[MEDIUM] Harden `book_meta` writes.** Options: only allow INSERT when the ISBN isn't already present *and* rate-limit inserts per user (needs a trigger), or move enrichment writes behind the `/api/*` proxy with the service key. Simplest honest fix: document it as accepted risk for a 2-user app. Effort: M for the trigger, S to accept. **Owner decision.**
8. **[LOW] Verify `covers` bucket storage policies in the Supabase dashboard** — confirm no `INSERT`/`UPDATE`/`DELETE` for `authenticated` on `storage.objects` where `bucket_id='covers'`. Effort: S (read-only check).
9. **[LOW] Remove `ollama` from the server.py provider allowlist** (or keep it only when explicitly enabled), and consider swapping vendored `quagga` 0.12.1 for `@ericblade/quagga2` next time the scanner is touched. Effort: S.
10. **[INFO] Neutralize "Her dark little library"** in `manifest.json` / `index.html` if the privacy posture from SEC-11 matters to him. Effort: S. **Owner decision.**

## Verified clean

- **Secrets in git:** working tree and post-2026-09-20 history swept for key/JWT/token patterns — clean (only false positives: SVG data-URIs, vendored supabase-js). `server-config.json` is gitignored; the example file contains no real values.
- **Secret handling:** Hardcover/Google Books/trope keys never leave the server — `/config.js` (both `server.py:156-174` and `functions/config.js.js`) carries only booleans/flags; the Supabase `service_role` key is used only server-side (`server.py:686-689`) and never serialized to clients.
- **SSRF guards:** cover-proxy uses a tight host allowlist on both stacks (`functions/cover-proxy.js:18-24`, `server.py:177-189` + DNS-based private/loopback/link-local/multicast/reserved blocking at `:193-211` with redirect-hop re-validation at `:246-259`); `/api/cache-cover` allowlists hosts (`server.py:177-189`); `/api/gbooks` is pinned to `www.googleapis.com/books/v1/volumes` (`server.py:871-876`); trope-infer providers are allowlisted with model-charset validation (`functions/api/trope-infer.js:36-38,94-104`).
- **RLS:** `books`, `deleted_books`, `profiles` are strict `auth.uid() = user_id` (`supabase/schema.sql:23-25,109-111,132-134`); circle tables enforce requester/addressee roles per action (`:168-186`); friend book reads respect `share_library` + `hidden_shelves` (`:238-258`); avatar storage is folder-per-user with friend-read-only (`:261-281`); `book_meta` attribution trigger prevents column spoofing (`:70-88`); trope/admin writes are `is_admin()`-gated (`supabase/tropes.sql`, `supabase/analytics.sql` with `SECURITY DEFINER`).
- **Auth flows:** mandatory sign-in gate (`js/095-gate.js`, `js/200-boot.js:33-46`); Google OAuth via Supabase PKCE (`sb.auth.exchangeCodeForSession`, `js/090-sync.js:412-420`); password reset via Supabase with no account-enumeration in UI copy; avatar upload paths are `user.id`-derived (`js/105-account.js:100`).
- **Service worker:** versioned cache name forces refetch per release; `/config.js` and `/api/*` explicitly bypass the cache (`sw.js:76-77`); cover cache is restricted to canonical bucket URLs with size-based eviction.
- **Analytics:** enum/count-only allowlist enforced in `track()` (`js/065-analytics.js:139-165`); no titles, ratings, notes, emails, or query text.
- **Client hygiene:** no `eval`/`new Function`/string timers/`postMessage` listeners in `js/`; no open redirects (storefront URLs are hardcoded domains); no `javascript:` URLs.
- **Rate limiting:** present on every quota-spending proxy on both stacks (with the documented distributed-attacker limitation noted in SEC-02).
- **Supply chain:** only two vendored deps, pinned with a `SOURCES.txt`; supabase-js 2.117.2 is current; quagga 0.12.1 has no applicable CVEs (see SEC-07).
